Project Brief · 01

项目概述OVERVIEW

摄影类产品的竞争点正在从「拍得好不好」转向「知不知道什么时候、去哪里拍」。 拾光用一套军事侦察的界面语言，把抽象的光线窗口变成可查询、可计划、可结算的行动系统。

项目背景

BACKGROUND

城市摄影的核心痛点是「时间 + 位置」的不确定：用户在多个 App 之间拼凑天气、日落时刻与机位信息，往往到达时已经错过最佳光线。

设计目标

GOALS

把光线窗口变成可视化、可倒计时的界面语言；建立一套统一编号与色带语义，让地图、详情、计划、档案四页彼此串联。

核心挑战

CHALLENGE

游戏化叙事容易沦为「贴徽章」。真正的难点是把奖励挂到真实行为上——拍到了什么光线、命中了几个窗口、什么时候出门。

Interface Design · 02

核心界面SIX SCREENS

视觉语言取自战术侦察终端：深墨底 #141619、 羊皮纸信息面板、军用模板大编号、等宽读数，强调色只有金色一种。

01
作战终端（主菜单）
RECON TERMINAL

等级与经验、当前行动卡、四宫格模块入口与战况速览。作为总入口，把「继续行动」放在最顺手的位置。

02
光影侦察地图 亮点一
SECTOR MAP

全屏战术地图：网格 + 斜线阴影区 + 手绘金色扇区边界 + 虚线航线串联 01–06 目标点，当前目标带脉冲环与四向准星。角上叠 HUD：光况胶囊、光线指数徽章、比例尺与指北针。

03
点位详情 · 时间轴 亮点二
TARGET FILE

档案卡 + 天空预览 + 坐标读数，核心是一根「光线窗口时间轴」：细刻度尺、七段光线色带（夜→晨光→浅金→白昼→黄金→蓝调→夜）、金色播放头与三个窗口标记。把一天的可用时间一眼读完。

04
作战简报（拍摄计划）
MISSION BRIEF

日期条 + 作战卡列表，编号与地图点位严格一致；每张卡带窗口时间与状态胶囊（待命 / 已部署），下方是光况风险与预计收益读条。

05
影像档案（我的光影日志）
IMAGE ARCHIVE

军衔卡与统计数据，六张底片各自用当次拍摄的光线渐变做封面并复用编号，底部是徽章墙。让每次出门都留下可累积的痕迹。

06
行动结算 · 战报
MISSION REPORT

收尾游戏循环：评级徽章（S 级）、四项数据（光线命中率 / 窗口命中 / 获得底片 / 用时）、经验结算明细与晋升进度条，再加上时间轴复盘，把「这一次到底打得怎么样」讲清楚。

Game Loop · 03

串联逻辑ONE NUMBER, FOUR SCREENS

游戏化最容易散架的地方是「每页各说各话」。拾光用同一套编号贯穿四个页面， 让玩家在地图上锁定的目标，能一路追到结算与图鉴。

接单

ACCEPT

把城市光点包装成「行动委托」，降低决策成本，先让人愿意出门。

侦察与抵达

RECON · ARRIVE

地图 + 时间轴解决「去哪、几点」；倒计时与行动清单解决路上焦虑。

拍摄与上传

SHOOT · UPLOAD

窗口进度条让人安心拍完；按下快门即生成底片卡片，归档零成本。

结算与成长

REPORT · PROGRESS

评级、经验、徽章与军衔把一次行动变成可累积的长期进度。
